## 3. 엔진 버그 수정: Whipsaw 방지 강화

5년 백테스트에서 추세 추종 계열 전략이 -90% 이상 손실을 기록하는 원인을 분석하여 세 가지 근본적 결함을 수정했다.

### 3.1 쿨다운 적용 범위 확대

| 항목 | 수정 전 | 수정 후 |
|------|---------|---------|
| 쿨다운 적용 조건 | 리스크 청산(Stop Loss, Take Profit)에만 | **모든 청산**(리스크 + 전략 시그널 매도 포함) |
| 쿨다운 기간 | 3 거래일 | **5 거래일** |

**문제 원인**: 전략 시그널에 의한 매도 후에는 쿨다운이 적용되지 않아, 매도 다음날 조건이 다시 충족되면 **즉시 재매수 -> 재매도**를 반복하는 왕복 거래(whipsaw)가 발생했다. `lt`/`gt` 조건은 임계값 아래/위에 있는 **매일** 시그널이 발생하므로, 쿨다운 없이는 매일 매수-매도가 반복된다.

### 3.2 최소 보유 기간 도입 (전략 매도용)

| 항목 | 수정 전 | 수정 후 |
|------|---------|---------|
| 전략 시그널 매도 최소 보유 | 없음 | **5 거래일** |

**문제 원인**: 매수 당일 또는 익일에 매도 조건이 충족되면 즉시 매도가 발생하여 수수료(0.015%) + 세금(0.23%) + 슬리피지(0.1%) = **왕복 약 0.46%**의 비용만 소진되었다. 최소 보유 기간을 두어 의미 있는 가격 변동이 일어날 시간을 확보했다.

### 3.3 리스크 매니저에도 최소 보유 기간 적용 (2차 수정)

| 항목 | 수정 전 (1차) | 수정 후 (2차) |
|------|-------------|--------------|
| Stop Loss/Take Profit 최소 보유 | 없음 (매수 다음날 발동 가능) | **5 거래일** |

**문제 원인**: 1차 수정에서 전략 시그널 매도에만 최소 보유 기간을 적용했으나, **리스크 매니저(Stop Loss/Take Profit)는 여전히 보유 기간 제한 없이 발동**되었다. 변동성이 큰 종목(TSLA, NVDA 등)에서 매수 직후 4~5% 하락이 빈번하게 발생하여, 전략 시그널이 매도하기도 전에 Stop Loss가 포지션을 청산했다. 이것이 MACD(-98.75%), 트리플 스크린(-92.50%)의 핵심 원인이었다.

**수정 내용** (`engine.py`의 `_process_day` 메서드):
```python
# 리스크 기반 청산 실행 + 쿨다운 등록
for exit_result in risk_exits:
    # 최소 보유 기간 체크: 매수 직후 stop loss 발동 방지
    if exit_result.symbol in self._portfolio.positions:
        pos = self._portfolio.positions[exit_result.symbol]
        days_held = (current_date - pos.entry_date).days
        if days_held < self._min_holding_days:
            continue
```

## 6. 진단: 왜 추세 추종 전략이 손실을 내는가

### 6.1 근본 원인: Level 조건의 구조적 한계

추세 추종, 골든크로스, MACD 크로스오버 등 대부분의 손실 전략은 `gt`(greater than) / `lt`(less than) 조건을 사용한다.

```
문제 시나리오 (gt/lt 조건):
- 매수 조건: SMA(20) > SMA(50)    ← gt 조건
- 매도 조건: SMA(20) < SMA(50)    ← lt 조건

Day 1: SMA(20) = 101, SMA(50) = 100  → 매수 시그널 발생
Day 2: SMA(20) = 101, SMA(50) = 100  → 매수 시그널 또 발생
Day 3: SMA(20) = 99,  SMA(50) = 100  → 매도 시그널 발생
Day 4: SMA(20) = 101, SMA(50) = 100  → 매수 시그널 또 발생
  ...
```

`gt`/`lt` 조건은 **전환 시점이 아니라, 해당 상태에 있는 매일** 시그널을 발생시킨다. SMA(20)이 SMA(50) 위에 있는 50일 동안 매일 매수 시그널이 발생하고, 이미 포지션이 있으면 무시되지만, 매도 직후 즉시 재매수가 발생한다.

### 6.2 쿨다운 수정 전: 왕복 거래 폭주

엔진 수정 전에는 전략 시그널 매도 후 쿨다운이 적용되지 않았다. 이로 인해:

1. 매도 조건 충족 -> 매도 실행
2. 같은 날 또는 익일, 매수 조건이 여전히 충족 -> 즉시 재매수
3. 재매수 후 매도 조건 다시 충족 -> 재매도
4. **반복 왕복 거래**: 왕복당 비용 0.46% 누적

이 패턴이 5년간 수백 회 반복되면서 자본이 기하급수적으로 감소했다.

### 6.3 RSI 전략이 생존하는 이유

RSI 기반 전략은 구조적으로 whipsaw에 강하다.

```
RSI 과매도 v2:
- 매수 조건: RSI(14) < 42
- 매도 조건: RSI(14) > 60

매수~매도 임계값 간격: 60 - 42 = 18포인트
```

RSI가 42에서 매수한 후 60까지 올라가려면 상당한 가격 변동이 필요하며, 이 사이 구간(42~60)에서는 매수도 매도도 발생하지 않는 **사각지대(dead zone)**가 존재한다. 이 사각지대가 자연스러운 보유 기간을 만들어 불필요한 왕복 거래를 방지한다.

반면, MACD 크로스오버의 매수/매도 조건은 MACD와 Signal Line의 교차로, 두 값이 근접한 구간에서 매일 교차가 뒤바뀌며 시그널이 폭증한다.

**증상**: 볼린저 밴드 스퀴즈, 평균 회귀 전략이 5년간 **거래 0건**.

**근본 원인**: `interpreter.py`의 `_parse_value_ref()` 로직에서 `"bollinger_20_lower"` 같은 비교 대상 문자열 파싱 실패.

```python
# 기존 코드 (버그)
parts = condition.value.rsplit("_", 1)
# "bollinger_20_lower".rsplit("_", 1) → ["bollinger_20", "lower"]

# → 볼린저 밴드가 비교 대상으로 사용될 때 지표 계산이 누락됨
```

**수정**: 정규식 기반 `_parse_value_ref()` 정적 메서드 신규 작성. `bollinger_{period}_{band}` 패턴을 먼저 매칭하여 올바르게 분리.

```python
@staticmethod
def _parse_value_ref(value: str, needed_indicators: set):
    bb_match = re.match(r'^bollinger_(\d+)_(upper|middle|lower)', value)
    if bb_match:
        period = int(bb_match.group(1))
        suffix = bb_match.group(2)
        bb_type = IndicatorType(f"bollinger_{suffix}")
        needed_indicators.add((bb_type, (("period", period),)))
        return
    # ... 기존 파싱 로직
```

| 전략 | 수정 전 | 수정 후 | 변화 |

| **결과** | -16.36% (C등급) | **+170.15%** (A등급) | **+186.51%p 개선** |

**공통 패턴**: 3개 전략 모두 RSI 역추세 진입(매수 RSI<40~45) + RSI 과매수 매도(RSI>65~70)로 전환하여 **데드존 패턴**을 적용. 이는 Section 6에서 분석한 "RSI 데드존이 수익의 핵심"이라는 교훈의 직접적 적용.

### 17.3 크로스-심볼 지표 구현

`per_sector_ratio`와 `momentum_3m` 랭킹을 위한 **크로스-심볼 계산 아키텍처**를 엔진에 추가.

#### 엔진 실행 흐름 변경

```
기존: _initialize → _load_data → _precompute_indicators → daily loop
변경: _initialize → _load_data → ★_compute_cross_symbol_indicators★ → _precompute_indicators → daily loop
```

#### 구현 내용

| 지표 | 파일 | 로직 |
|------|------|------|
| `per_sector_ratio` | `engine.py::_compute_per_sector_ratio()` | 섹터별 평균 PER 계산 → 개별 종목 PER / 섹터 평균 |
| `momentum_3m_top_n` | `engine.py::_compute_momentum_ranking()` | 날짜별 3개월 수익률 계산 → 상위 N개 심볼 boolean 플래그 |

#### data_loader_mongo.py 변경

- `include_sector` 파라미터 추가: MongoDB `stocks.{symbol}.info.sector` 로드
- 펀더멘탈/섹터 데이터 `ffill()` 추가: 휴일/결측 대응

#### 데이터 제약 사항

MongoDB의 `info` 필드(PER, dividend_yield 등)는 **2026-02-20부터만 존재** (6일). 따라서:
- `high_dividend`: 거래 0건 (배당률 데이터 없는 기간이 대부분)
- `low_per_value`: 거래 0건 (PER 데이터 없는 기간이 대부분)
- 향후 info 데이터 수집 기간이 쌓이면 자연스럽게 해결

1. **파싱 버그 하나가 전략 2개를 완전히 죽일 수 있다**: 볼린저 파싱 버그로 2개 전략이 5년간 거래 0건. 코드 리뷰와 단위 테스트의 중요성.

2. **Buy Weakness > Buy Strength**: 추세 추종 전략을 역추세 진입(RSI dip buy)으로 전환하자 3개 전략 모두 대폭 개선. 현재 종목 풀(대형 테크주)에서는 "상승 추세 내 눌림목 매수"가 최적.

3. **데드존 패턴의 보편적 적용 가능성**: RSI 과매도에서 발견된 데드존 패턴이 추세 추종, 듀얼 모멘텀, 트리플 스크린에도 동일하게 효과적.

4. **크로스-심볼 지표는 데이터 종속적**: per_sector_ratio, momentum_3m 랭킹은 아키텍처적으로 구현 완료했으나, MongoDB info 데이터(6일)로는 충분한 검증 불가.
