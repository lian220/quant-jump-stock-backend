# AI 분석 (Vertex AI 예측)

**최종 업데이트**: 2026-02-22

---

## 개요

Google Vertex AI Custom Training Jobs를 활용하여 Transformer 모델 기반의 주가 예측을 수행합니다.
Core API(Spring Boot)에서 요청을 받아 Pub/Sub으로 Data Engine(Python)에 전달하고,
Data Engine이 GCS에 ML 패키지를 업로드한 뒤 Vertex AI CustomJob으로 GPU 학습을 실행합니다.

### 핵심 설계 원칙

- **비동기 실행**: API 호출 즉시 응답, 실제 학습은 Vertex AI에서 비동기 처리
- **Slack 스레드 알림**: 시작 → 완료/실패까지 동일 스레드에서 추적
- **Cold Start 최적화**: `google-cloud-aiplatform` (~8초) Lazy Import
- **헥사고날 아키텍처**: Core API / Data Engine 모두 Ports & Adapters 준수

## Fine-Tuning vs Full Training

### Fine-Tuning (기본 모드)

기존에 학습된 모델의 가중치를 유지하면서, **최근 데이터만으로 미세 조정**하는 방식입니다.

| 항목 | 값 |
|------|-----|
| Epochs | 5 |
| Learning Rate | 0.00005 |
| 소요 시간 | 3~5분 |
| 비용 | ~$0.05/회 |
| 사용 시점 | 매일/주간 정기 예측 |

**동작 원리:**
1. GCS(`ml-models/latest/model.keras`)에서 기존 모델 로드
2. 모델 아키텍처 호환성 검증 (input shape 비교)
3. 낮은 Learning Rate(0.00005)로 5 epochs 추가 학습
4. 학습된 모델을 GCS에 저장 (날짜별 + latest)

**Fallback:** GCS에 모델이 없거나 아키텍처 불일치 시 → Full Training으로 자동 전환

**장점:** 빠르고 저렴, 기존 학습 결과 보존
**단점:** 시장 구조가 크게 바뀌면 기존 가중치가 오히려 방해

### Full Training (전체 학습)

모델을 처음부터 다시 학습합니다.

| 항목 | 값 |
|------|-----|
| Epochs | 50 |
| Learning Rate | 0.0001 |
| 소요 시간 | 20~30분 |
| 비용 | ~$0.23/회 |
| 사용 시점 | 월간 또는 종목 변경 시 |

**동작 원리:**
1. 모델 가중치를 랜덤 초기화
2. 전체 학습 데이터(~260일)로 처음부터 학습
3. 학습 완료 후 모델을 GCS에 저장 (이후 Fine-tuning의 기반)
4. 새 모델을 GCS에 저장

**장점:** 시장 구조 변화에 강함, 깨끗한 학습
**단점:** 시간 + 비용 소모, GPU 할당량 점유

### 스케줄러 자동 선택

| 요일 | 모드 | 이유 |
|------|------|------|
| 월~토 | Fine-tuning | 빠르고 저렴한 일일 갱신 |
| 일요일 | Full Training | 주간 완전 재학습으로 정확도 유지 |

### 환경변수 설정

```bash
# Fine-tuning (기본)
FINE_TUNE_MODE=true
FINE_TUNE_EPOCHS=5
FINE_TUNE_LR=0.00005

# Full Training
FINE_TUNE_MODE=false
FULL_TRAIN_EPOCHS=50
FULL_TRAIN_LR=0.0001

# GCS 모델 저장 경로
VERTEX_AI_MODEL_BUCKET=focal-limiter-stock-trading-packages
VERTEX_AI_MODEL_BASE_PATH=ml-models
```

### API 호출

```bash
# Fine-tuning (기본)
curl -X POST /api/v1/admin/vertex-ai/predict \
  -H "Content-Type: application/json" \
  -d '{"fineTune": true}'

# Full Training
curl -X POST /api/v1/admin/vertex-ai/predict \
  -H "Content-Type: application/json" \
  -d '{"fineTune": false}'
```

## ML 모델 아키텍처

### Transformer 기반 2-Input 모델

```
Input 1: 주가 시계열 (90일 lookback)
    → 4x Transformer Encoder (8-head attention, FF dim 256)
    → Dense(64)
                    ↓
                  Merge → Dense(128) → GlobalAveragePooling1D → Output
                    ↑
Input 2: 경제 지표 시계열 (90일 lookback)
    → 4x Transformer Encoder (8-head attention, FF dim 256)
    → Dense(64)
```

### 모델 파라미터

| 파라미터 | 값 |
|----------|-----|
| Lookback | 90일 |
| Forecast Horizon | 14일 (14일 후 종가 예측) |
| Attention Heads | 8 |
| FF Dimension | 256 |
| Encoder Blocks | 4 per stream |
| Dropout Rate | 0.1 (attention), 0.2 (dense) |
| Optimizer | Adam (lr=0.0001) |
| Loss | MSE |
| Scaler | MinMaxScaler (주가, 경제 지표 별도) |

### 입력 데이터

| 소스 | 데이터 | 출처 |
|------|--------|------|
| MongoDB | 일별 OHLCV (시가/고가/저가/종가/거래량) | daily_stock_data.stocks |
| MongoDB | 시장 지수 (S&P 500, NASDAQ 등) | daily_stock_data.yfinance_indicators |
| MongoDB | FRED 경제지표 (금리, CPI, 실업률 등) | daily_stock_data.fred_indicators |

### 출력 데이터

| 항목 | 설명 |
|------|------|
| 14일 가격 예측 | 종목별 향후 14일 종가 예측 |
| 상승 확률 | 각 종목의 상승/하락 확률 |
| 신뢰도 점수 | MAPE 기반 예측 신뢰 수준 |
| 투자 추천 | STRONG BUY / BUY / HOLD / SELL |

## 예측 품질 게이트

MAPE(Mean Absolute Percentage Error) 기반으로 저신뢰 예측을 자동 필터링합니다.

| 항목 | 값 |
|------|-----|
| **임계값** | `MAX_RELIABLE_MAPE = 30.0%` |
| **적용 위치** | `predict_optimized.py` → `generate_recommendation()`, `save_predictions_to_db()` |

**추천 분류:**

| 추천 | 조건 |
|------|------|
| `STRONG BUY` | 상승 예측 & rise_prob > 2% & MAPE ≤ 30% |
| `BUY` | 상승 예측 & rise_prob ≤ 2% & MAPE ≤ 30% |
| `HOLD (Low Confidence)` | MAPE > 30% (예측 신뢰도 낮음) |
| `SELL` | 하락 예측 & MAPE ≤ 30% |

> NVDA(153%), TSLA(53%), AVGO(40%) 등 고오류 종목의 잘못된 매수 신호를 방지.

## 데이터 흐름 (predict_optimized.py)

1. MongoDB 연결 → `daily_stock_data`에서 최근 24개월 데이터 로드
2. PostgreSQL → `stocks`(활성 종목), `fred_indicators`, `yfinance_indicators` 로드
3. 데이터 전처리: NaN 처리 (ffill → bfill → 0 fill), MinMaxScaler
4. Transformer 모델 학습 (또는 Fine-tuning)
5. 전체 기간 예측 수행
6. 역변환(inverse_transform) → 실제 가격 복원
7. MongoDB `stock_predictions`에 저장
8. Slack 알림 발송 (성공/실패)


## 에러 처리

### 재시도 불가 에러 (즉시 ACK)

```python
_NON_RETRYABLE_PATTERNS = [
    "permission denied", "403", "unauthorized", "401",
    "not found", "404", "invalid", "credentials",
    "quota exceeded", "billing", "disabled",
]
```

- 인증 실패, 할당량 초과, API 미활성화 등
- Pub/Sub 메시지를 즉시 ACK하여 무한 재시도 방지

### 재시도 가능 에러

- 네트워크 타임아웃, 일시적 서비스 불가
- Pub/Sub 기본 재시도 정책(지수 백오프) 적용

### 트러블슈팅

| 에러 | 원인 | 해결 |
|------|------|------|
| `RESOURCE_EXHAUSTED` (429) | GPU 할당량 초과 | GCP Console에서 quota 증가 신청 |
| `PERMISSION_DENIED` (403) | SA 권한 부족 | IAM에서 역할 추가 |
| `NOT_FOUND` (404) | 패키지 없음 | `/api/v1/ml/upload`으로 업로드 |
| `connection timeout` | DB 연결 실패 | `.env.db.prod` 확인, IP 허용 목록 확인 |

Vertex AI CustomJob에서 T4 GPU를 사용하려면 할당량 신청이 필요합니다.

1. [GCP Console → Quotas](https://console.cloud.google.com/apis/api/aiplatform.googleapis.com/quotas?project=focal-limiter-486614-u8) 접속
2. 필터: `Custom model training Nvidia T4 GPUs per region`
3. `us-central1` 리전 선택
4. 할당량을 **1**로 증가 요청
