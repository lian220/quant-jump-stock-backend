## 📊 데이터 분류

### PostgreSQL - 정형 데이터

| 테이블 | 데이터 유형 | 이유 |
|--------|-------------|------|
| **stocks** | 주식 메타데이터 | 고정 스키마, 관계형, 자주 조인 |
| **users** | 사용자 정보 | ACID 필요, 인증 데이터 |
| **trading_configs** | 거래 설정 | users FK, 트랜잭션 |
| **trades** | 거래 내역 | ACID 필수, 금융 데이터 |
| **account_balances** | 계좌 잔고 | 트랜잭션, 정합성 중요 |
| **stock_holdings** | 보유 주식 | users/stocks FK |
| **kis_tokens** | KIS 토큰 | 보안 데이터, 암호화 |

**특징**:
- ✅ 고정된 스키마
- ✅ ACID 트랜잭션 보장
- ✅ 외래 키 제약
- ✅ 복잡한 조인 쿼리
- ✅ 데이터 정합성 중요

### MongoDB - 비정형 데이터

| 컬렉션 | 데이터 유형 | 이유 |
|--------|-------------|------|
| **daily_stock_data** | 일별 주식 데이터 | 복잡한 nested, 빠른 쓰기 |
| **prediction_results** | Vertex AI 예측 | JSON 결과, 유동적 스키마 |
| **stock_recommendations** | AI 추천 결과 | 기술적 지표 (동적 필드) |
| **sentiment_analysis** | 감정 분석 | 뉴스 데이터, 비정형 |
| **stock_analysis_results** | 종합 분석 | 복잡한 분석 결과 |

**특징**:
- ✅ 유동적 스키마
- ✅ 복잡한 nested documents
- ✅ 대용량 로그 데이터
- ✅ 빠른 읽기/쓰기
- ✅ ML/AI JSON 결과

## 🔄 데이터 흐름

### 정형 데이터 흐름 (PostgreSQL)

```
사용자 거래 요청
    ↓
1. users 테이블에서 사용자 확인
    ↓
2. stocks 테이블에서 종목 검증
    ↓
3. trading_configs에서 거래 설정 확인
    ↓
4. trades 테이블에 거래 기록 (ACID)
    ↓
5. account_balances 업데이트 (ACID)
    ↓
6. stock_holdings 업데이트 (ACID)

✅ 트랜잭션으로 모두 성공 또는 롤백
```

### 비정형 데이터 흐름 (MongoDB)

```
ML/AI 분석 요청
    ↓
1. daily_stock_data에서 historical 데이터 조회
    ↓
2. Vertex AI 예측 실행
    ↓
3. prediction_results에 JSON 결과 저장
    ↓
4. stock_recommendations 생성 (기술적 지표 포함)
    ↓
5. sentiment_analysis 추가
    ↓
6. stock_analysis_results 종합 (모든 분석 통합)

✅ 각 단계는 독립적, 빠른 쓰기
```

### 백테스트 데이터 통합 (MongoDB 3개 컬렉션 Left Join)

> **핵심 전략**: daily_stock_data + sentiment_analysis + stock_recommendations 통합
>
> **상세 문서**: [백테스트_데이터_통합_전략.md](./백테스트_데이터_통합_전략.md)

```
백테스트 요청
    ↓
1. MongoDataLoader.load()
    ↓
2. daily_stock_data 조회 (OHLCV 기본)
    ├─ include_sentiment=True
    │  └─> sentiment_analysis 조회
    └─ include_recommendations=True
       └─> stock_recommendations 조회
    ↓
3. Left Join 수행 (ticker + date)
    ├─ OHLCV (기준)
    ├─ sentiment_score, sentiment_count (옵션)
    └─ is_recommended, rec_rsi, rec_score (옵션)
    ↓
4. DataFrame 반환
    {
      "AAPL": DataFrame[
        date, open, high, low, close, volume,
        sentiment_score, sentiment_count,
        is_recommended, rec_rsi, rec_score
      ]
    }
    ↓
5. BacktestEngine 실행
    ├─ SCREENING 전략 (감성 기반)
    └─ PORTFOLIO 전략 (기술적 지표 기반)

✅ Left Join으로 유연한 데이터 선택
✅ 결측값 기본값 처리 (0.0, False 등)
✅ SCREENING/PORTFOLIO 이원화 지원
```

**Left Join 예시**:
```python
# 감성 + 추천 모두 활용
loader = MongoDataLoader()
data = loader.load(
    symbols=["AAPL", "NVDA"],
    start_date=date(2025, 1, 1),
    end_date=date(2025, 1, 31),
    include_sentiment=True,
    include_recommendations=True
)

# 결과 DataFrame
"""
date                open    close   sentiment_score  is_recommended
2025-01-01 00:00:00 150.0   153.0   0.75             True
2025-01-02 00:00:00 153.0   157.0   0.80             True
2025-01-03 00:00:00 157.0   158.0   0.0              False  (결측값)
"""
```

## 🔗 하이브리드 연동

### stocks 데이터 참조

**PostgreSQL stocks (Source of Truth)**:
```kotlin
// 거래 시 종목 검증
val stock = stockJpaRepository.findByTicker("AAPL")
if (stock == null || !stock.isActive) {
    throw InvalidStockException("Invalid or inactive stock")
}
```

**MongoDB에서 참조**:
```kotlin
// 예측 결과에 ticker만 저장
val prediction = PredictionResult(
    symbol = "AAPL",  // ← PostgreSQL stocks의 ticker 참조
    prediction = 150.5,
    confidence = 0.85
)
predictionRepository.save(prediction)
```

**조인 패턴**:
```kotlin
// Application Layer에서 조합
fun getStockWithPredictions(ticker: String): StockWithPrediction {
    val stock = stockJpaRepository.findByTicker(ticker)  // PostgreSQL
    val predictions = predictionRepository.findBySymbol(ticker)  // MongoDB
    return StockWithPrediction(stock, predictions)
}
```

## 📋 마이그레이션 가이드

### stocks 데이터 마이그레이션 (완료)

**Before (MongoDB Only)**:
```kotlin
@Document(collection = "stocks")
data class Stock(
    @Id val id: String?,
    val ticker: String,
    val stockName: String,
    // ...
)

interface StockRepository : MongoRepository<Stock, String>
```

**After (PostgreSQL + MongoDB Hybrid)**:
```kotlin
// PostgreSQL (정형 메타데이터)
@Entity
@Table(name = "stocks")
data class StockEntity(
    @Id @GeneratedValue val id: Long?,
    @Column(unique = true) val ticker: String,
    val stockName: String,
    // ...
)

interface StockJpaRepository : JpaRepository<StockEntity, Long>

// MongoDB (비정형 분석 데이터만)
@Document(collection = "prediction_results")
data class PredictionResult(
    @Id val id: String?,
    val symbol: String,  // ← PostgreSQL stocks.ticker 참조
    // ...
)
```

## ⚠️ 주의사항

### 1. MongoDB stocks 컬렉션 삭제 예정

**현재 상태**:
- MongoDB stocks: 35개 데이터 (미사용)
- PostgreSQL stocks: 35개 데이터 (활용 중)

**삭제 계획**:
```bash
# ⚠️ 주의: 실제 실행 전 백업 필수
# MongoDB stocks 컬렉션 삭제
docker compose exec mongodb mongosh stock_trading \
  --authenticationDatabase admin \
  -u quantiq_user -p quantiq_password \
  --eval "db.stocks.drop()"
```

### 2. 데이터 정합성 유지

**ticker를 공통 키로 사용**:
- PostgreSQL stocks.ticker (Primary Key)
- MongoDB collections의 symbol/ticker 필드 (Reference)

**정합성 규칙**:
1. PostgreSQL stocks에 없는 ticker는 MongoDB에 저장 금지
2. stocks.is_active = false면 예측/분석 중단
3. ticker 변경 시 양쪽 모두 업데이트

### 3. 성능 고려사항

**PostgreSQL**:
- 인덱스: ticker, is_active, sector, industry
- 조인 쿼리 최적화
- 트랜잭션 범위 최소화

**MongoDB**:
- symbol 필드 인덱스
- 복합 인덱스: {symbol: 1, date: -1}
- 샤딩 고려 (대용량 시)
