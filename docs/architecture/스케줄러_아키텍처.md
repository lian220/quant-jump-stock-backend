# 스케줄러 아키텍처

**목적**: Quartz 스케줄러 시스템의 구조와 설계 설명
**대상**: 개발자, 시스템 관리자
**최종 업데이트**: 2026-02-13

---

## 개요

QuantIQ 스케줄러는 **Quartz Scheduler**를 기반으로 하며, **Hexagonal Architecture** 패턴을 적용하여 구현되었습니다.

### 주요 특징

- **정기 작업 자동화**: 경제 데이터 업데이트, 병렬 분석 등을 자동으로 실행
- **유연한 스케줄 관리**: Cron 표현식을 사용한 정밀한 시간 제어
- **영속성 지원**: PostgreSQL에 스케줄 상태 저장 (애플리케이션 재시작 시에도 유지)
- **클러스터링 지원**: 분산 환경에서 안전한 Job 실행
- **REST API**: HTTP API를 통한 스케줄러 제어 (pause/resume/start/stop)

### 기술 스택

| 구성 요소 | 기술 |
|----------|------|
| 스케줄러 | Quartz Scheduler 2.3+ |
| 언어 | Kotlin |
| 프레임워크 | Spring Boot 3.x |
| 아키텍처 | Hexagonal Architecture |
| 저장소 | PostgreSQL (JDBC JobStore) |
| 타임존 | Asia/Seoul (KST) |

## Hexagonal Architecture 적용

```
┌─────────────────────────────────────────────────────────────┐
│                      Input Adapters                         │
├─────────────────────────────────────────────────────────────┤
│  SchedulerRestController    EconomicDataUpdate2JobAdapter   │
│  (REST API)                 ParallelAnalysisJob             │
│                             AutoBuyJobAdapter ...           │
└────────────────┬─────────────────────┬──────────────────────┘
                 │                     │
                 ↓                     ↓
┌─────────────────────────────────────────────────────────────┐
│                   Domain Layer (Port)                       │
├─────────────────────────────────────────────────────────────┤
│  Input Port:  SchedulerUseCase                              │
│  Output Port: SchedulerRepository                           │
└────────────────┬────────────────────────────────────────────┘
                 │
                 ↓
┌─────────────────────────────────────────────────────────────┐
│                  Application Layer                          │
├─────────────────────────────────────────────────────────────┤
│  SchedulerManagementService (UseCase 구현)                  │
└────────────────┬────────────────────────────────────────────┘
                 │
                 ↓
┌─────────────────────────────────────────────────────────────┐
│                   Output Adapters                           │
├─────────────────────────────────────────────────────────────┤
│  QuartzSchedulerAdapter (Repository 구현)                   │
│  ↓                                                          │
│  Quartz Scheduler → PostgreSQL                              │
└─────────────────────────────────────────────────────────────┘
```

### 주요 컴포넌트

| 컴포넌트 | 역할 | 경로 |
|----------|------|------|
| `SchedulerRestController` | HTTP 요청 → UseCase 전달 | `adapter/input/rest/scheduler/` |
| `QuartzConfig` | Job 및 Trigger 등록 | `scheduler/QuartzConfig.kt` |
| `SchedulerUseCase` | Input Port (인터페이스) | `domain/scheduler/port/input/` |
| `SchedulerRepository` | Output Port (인터페이스) | `domain/scheduler/port/output/` |
| `SchedulerManagementService` | UseCase 구현체 | `application/scheduler/` |
| `QuartzSchedulerAdapter` | Quartz 연동 Repository 구현 | `adapter/output/persistence/` |

## Kafka 이벤트 통합

스케줄러는 Kafka를 통해 Data Engine과 통신합니다.

### 발행 토픽 (Core → Data Engine)

| 토픽 | 발행 Job | 용도 |
|------|---------|------|
| `economic.data.update.request` | EconomicDataUpdate2JobAdapter | 경제 데이터 수집 요청 |
| `analysis.technical.request` | ParallelAnalysisJob | 기술적 분석 요청 |
| `analysis.sentiment.request` | ParallelAnalysisJob | 감정 분석 요청 |
| `vertex.ai.run.request` | EconomicDataUpdate2JobAdapter | Vertex AI 예측 실행 요청 |

### 이벤트 흐름

```
Quartz Trigger → Job Adapter → UseCase → Kafka Producer
                                              ↓
                                         Kafka Broker
                                              ↓
                              Data Engine → Kafka Handler → Service → MongoDB
```

## Quartz 설정

### QuartzConfig.kt

```kotlin
@Configuration
@DependsOn("flywayInitializer")  // Flyway 마이그레이션 후 초기화
class QuartzConfig {
    // JobDetail + Trigger Bean 등록
    // Cron: CronScheduleBuilder.cronSchedule("0 0 22 * * ?")
    // Simple: SimpleScheduleBuilder.simpleSchedule().withIntervalInMinutes(1)
}
```

### application.yml

```yaml
spring:
  quartz:
    job-store-type: jdbc
    jdbc:
      initialize-schema: never     # Flyway가 스키마 관리
    properties:
      org.quartz.scheduler.instanceName: QuantIQScheduler
      org.quartz.scheduler.instanceId: AUTO
      org.quartz.jobStore.class: org.quartz.impl.jdbcjobstore.JobStoreTX
      org.quartz.jobStore.driverDelegateClass: org.quartz.impl.jdbcjobstore.PostgreSQLDelegate
      org.quartz.jobStore.tablePrefix: quartz_
      org.quartz.jobStore.isClustered: true
      org.quartz.threadPool.threadCount: 10
```

### PostgreSQL 테이블

Quartz 상태는 PostgreSQL에 저장됩니다. (마이그레이션: `V3__Create_Quartz_Tables.sql`)

| 테이블 | 역할 |
|--------|------|
| `quartz_job_details` | Job 메타데이터 |
| `quartz_triggers` | 트리거 정보 (next_fire_time, state) |
| `quartz_cron_triggers` | Cron 표현식 |
| `quartz_fired_triggers` | 실행 중/완료 Job |
| `quartz_scheduler_state` | 스케줄러 인스턴스 상태 |
| `quartz_locks` | 분산 락 (클러스터링) |

## 새 Job 추가 방법

1. **Job 클래스 작성** (`adapter/input/scheduler/`)
```kotlin
@Component
class NewJobAdapter(private val useCase: SomeUseCase) : Job {
    override fun execute(context: JobExecutionContext?) {
        useCase.doSomething()
    }
}
```

2. **QuartzConfig에 등록** (`scheduler/QuartzConfig.kt`)
```kotlin
@Bean
fun newJobDetail(): JobDetail =
    JobBuilder.newJob(NewJobAdapter::class.java)
        .withIdentity("newJob").storeDurably().build()

@Bean
fun newJobTrigger(): Trigger =
    TriggerBuilder.newTrigger()
        .forJob(newJobDetail())
        .withSchedule(CronScheduleBuilder.cronSchedule("0 0 12 * * ?")
            .inTimeZone(TimeZone.getTimeZone("Asia/Seoul")))
        .build()
```
