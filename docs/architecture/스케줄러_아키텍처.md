# 스케줄러 아키텍처

**목적**: 스케줄러 시스템의 구조와 설계 설명 (Cloud Scheduler + Core Quartz 이중 구조)
**대상**: 개발자, 시스템 관리자
**최종 업데이트**: 2026-03-01 (Core API Cloud Scheduler 전환 예정 반영)

---

## 개요

QuantIQ 스케줄러는 **이중 구조**로 운영됩니다:

| 계층 | 기술 | 담당 영역 |
|------|------|-----------|
| **Cloud Scheduler** | GCP Cloud Scheduler → Pub/Sub | 데이터 파이프라인 (경제데이터, 분석, 예측, 종목추천) |
| **Core Quartz** | Spring Quartz Scheduler | 트레이딩 (자동매수/매도, 주문정리, 보고) + 백테스트 |

### 설계 원칙

- **Cloud Scheduler**: 데이터 파이프라인은 Data Engine(Python)이 직접 처리 → Core 경유 불필요
- **Core Quartz**: 트레이딩/백테스트는 Core(Kotlin) 비즈니스 로직에 의존 → Quartz 유지
- **source 기반 cascade 제어**: `"pipeline"` = 자동 체이닝, `"standalone"` = 단독 실행

### 기술 스택

| 구성 요소 | 기술 |
|----------|------|
| 데이터 파이프라인 스케줄링 | GCP Cloud Scheduler |
| 메시징 | Google Cloud Pub/Sub |
| 트레이딩 스케줄링 | Quartz Scheduler 2.3+ |
| Core API | Spring Boot 3.x (Kotlin) |
| Data Engine | FastAPI (Python) |
| 저장소 (Quartz) | PostgreSQL (JDBC JobStore) |
| 타임존 | Asia/Seoul (KST) |

## 일일 스케줄 타임라인 (KST)

```
── Cloud Scheduler (데이터 파이프라인) ──────────────────────────
06:05  morning-economic-data     → 경제데이터 수집 (standalone, cascade 없음)
22~06  news-collection           → 뉴스 수집 (1분 간격)
06~22  news-collection-offhours  → 뉴스 수집 (5분 간격)
23:40  evening-pipeline          → 경제데이터 → 분석 → Vertex AI (pipeline, 체이닝)
00:20  stock-recommendation      → 종목 추천 (standalone, cascade 없음)

── Core Quartz (트레이딩) ──────────────────────────────────────
00:30  AutoBuyJobAdapter         → 자동 매수 (미국 장 개장 1시간 후)
매1분  AutoSellJobAdapter        → 자동 매도 체크 (미국 장중)
06:30  CleanupOrdersJobAdapter   → 미체결 주문 정리
07:00  PortfolioProfitReportJob  → 포트폴리오 수익 보고

── Core Quartz (백테스트) ──────────────────────────────────────
일 02:00  CanonicalBacktestJob   → PUBLISHED 전략 대표 백테스트
매일 03:00  BacktestCleanupJob   → RUNNING 타임아웃, 초과 아카이브 정리
```

## source 기반 cascade 제어

| source | 트리거 | cascade 동작 |
|--------|--------|-------------|
| `"pipeline"` | Cloud Scheduler evening-pipeline (23:40) | 완료 시 다음 단계 자동 트리거 |
| `"standalone"` | 그 외 모든 트리거 (Admin API, Cloud Scheduler 단독, Quartz 등) | 단독 실행, cascade 없음 |

### 파이프라인 체이닝 흐름 (source="pipeline")

```
Cloud Scheduler (23:40 KST)
  │ Pub/Sub: economic-data-update-request (source="pipeline")
  ▼
EconomicDataHandler
  │ 경제데이터 수집 완료
  │ source="pipeline" → 후속 트리거 발동
  ├──▶ Pub/Sub: analysis-technical-request
  └──▶ Pub/Sub: analysis-sentiment-request  (병렬)
       │
       ▼
TechnicalAnalysisHandler 완료
  │ source="pipeline" → 후속 트리거 발동
  ▶ Pub/Sub: vertex-ai-run-request
       │
       ▼
VertexAIRunHandler
  └ Vertex AI CustomJob 제출 (완료)
```

### standalone 호출 예시

```
Admin API: POST /api/v1/admin/economic-data/collections
  → source="standalone" (기본값)
  → 경제데이터 수집만 실행
  → 기술적 분석, Vertex AI 등 후속 트리거 없음
```

## Cloud Scheduler 상세

### 등록된 Job 목록

| # | Job 이름 | 스케줄 | Pub/Sub 토픽 | 역할 |
|---|---------|--------|-------------|------|
| 1 | morning-economic-data | 06:05 KST | economic-data-update-request | 경제데이터 수집 (standalone) |
| 2 | evening-pipeline | 23:40 KST | economic-data-update-request | 파이프라인 체이닝 (pipeline) |
| 3 | stock-recommendation | 00:20 KST | analysis-recommendation-request | 종목 추천 (standalone) |
| 4 | news-collection | */1 22-23,0-5 KST | HTTP → news-collector | 뉴스 수집 (미국장) |
| 5 | news-collection-offhours | */5 6-21 KST | HTTP → news-collector | 뉴스 수집 (비미장) |

**Core API용 (Cloud Run 전환 시)**  
`terraform/scheduler.tf`에 6개 HTTP 타겟 잡이 주석으로 정의됨. Core API를 Cloud Run으로 전환하면 Quartz 대신 이 잡들이 Core Run URL을 호출: `core-auto-buy`, `core-auto-sell`, `core-cleanup-orders`, `core-portfolio-report`, `core-canonical-backtest`, `core-backtest-cleanup`. 상세: [클라우드런_전환_Phase1.md](./클라우드런_전환_Phase1.md).

### Terraform 설정

Cloud Scheduler Job은 `terraform/scheduler.tf`에서 관리합니다.

```hcl
# 예: evening-pipeline
resource "google_cloud_scheduler_job" "evening_pipeline" {
  name     = "evening-pipeline"
  schedule = "40 23 * * *"
  time_zone = "Asia/Seoul"

  pubsub_target {
    topic_name = google_pubsub_topic.topics["economic-data-update-request"].id
    data = base64encode(jsonencode({
      eventType = "TRIGGER_ECONOMIC_DATA"
      payload = { source = "pipeline", requestId = "cs-evening-pipeline" }
    }))
  }
}
```

## Pub/Sub 이벤트 통합

Data Engine은 Pub/Sub를 통해 메시지를 수신합니다.

### 토픽 목록

| 토픽 | 발행자 | 구독자 | 용도 |
|------|--------|--------|------|
| `economic-data-update-request` | Cloud Scheduler | Data Engine | 경제 데이터 수집 |
| `analysis-technical-request` | Data Engine (체이닝) | Data Engine | 기술적 분석 |
| `analysis-sentiment-request` | Data Engine (체이닝) | Data Engine | 감정 분석 |
| `vertex-ai-run-request` | Data Engine (체이닝) | Data Engine | Vertex AI 예측 |
| `analysis-recommendation-request` | Cloud Scheduler | Data Engine | 종목 추천 |

> Core Admin API도 Pub/Sub 메시지를 발행할 수 있음 (source="standalone")

### 이벤트 흐름

```
Cloud Scheduler → Pub/Sub Topic → Data Engine Handler → Service → MongoDB/Slack
```

## Quartz 설정

### QuartzConfig.kt

```kotlin
@Configuration
@DependsOn("flywayInitializer")  // Flyway 마이그레이션 후 초기화
@ImportRuntimeHints(QuartzRuntimeHints::class)
class QuartzConfig {
    // JobDetail + Trigger Bean 등록
    // Cron: CronScheduleBuilder.cronSchedule("0 30 0 * * ?")
    // Simple: SimpleScheduleBuilder.simpleSchedule().withIntervalInMinutes(1)
}
```

### application.yml

```yaml
spring:
  quartz:
    job-store-type: jdbc
    jdbc:
      initialize-schema: never     # Flyway가 스키마 관리
    properties:
      org.quartz.scheduler.instanceName: QuantIQScheduler
      org.quartz.scheduler.instanceId: AUTO
      org.quartz.jobStore.class: org.quartz.impl.jdbcjobstore.JobStoreTX
      org.quartz.jobStore.driverDelegateClass: org.quartz.impl.jdbcjobstore.PostgreSQLDelegate
      org.quartz.jobStore.tablePrefix: quartz_
      org.quartz.jobStore.isClustered: true
      org.quartz.threadPool.threadCount: 10
```

### PostgreSQL 테이블

Quartz 상태는 PostgreSQL에 저장됩니다. (마이그레이션: `V3__Create_Quartz_Tables.sql`)

| 테이블 | 역할 |
|--------|------|
| `quartz_job_details` | Job 메타데이터 |
| `quartz_triggers` | 트리거 정보 (next_fire_time, state) |
| `quartz_cron_triggers` | Cron 표현식 |
| `quartz_fired_triggers` | 실행 중/완료 Job |
| `quartz_scheduler_state` | 스케줄러 인스턴스 상태 |
| `quartz_locks` | 분산 락 (클러스터링) |

## 새 Job 추가 방법

### Cloud Scheduler (데이터 파이프라인)

`terraform/scheduler.tf`에 새 리소스 추가 → `terraform apply`

### Core Quartz (트레이딩/백테스트)

1. **Job 클래스 작성** (`adapter/input/scheduler/`)
```kotlin
@Component
class NewJobAdapter(private val useCase: SomeUseCase) : Job {
    override fun execute(context: JobExecutionContext?) {
        useCase.doSomething()
    }
}
```

2. **QuartzConfig에 등록** (`scheduler/QuartzConfig.kt`)
```kotlin
@Bean
fun newJobDetail(): JobDetail =
    JobBuilder.newJob(NewJobAdapter::class.java)
        .withIdentity("newJob").storeDurably().build()

@Bean
fun newJobTrigger(): Trigger =
    TriggerBuilder.newTrigger()
        .forJob(newJobDetail())
        .withSchedule(CronScheduleBuilder.cronSchedule("0 0 12 * * ?")
            .inTimeZone(TimeZone.getTimeZone("Asia/Seoul")))
        .build()
```

3. **GraalVM Hints 등록** (`scheduler/QuartzRuntimeHints.kt`)
