## 스케줄 구성

### 이중 스케줄러 구조

| 계층 | 담당 | 기술 |
|------|------|------|
| **Cloud Scheduler** | 데이터 파이프라인 (경제데이터, 분석, 예측, 추천, 뉴스) | GCP Cloud Scheduler → Pub/Sub → Data Engine |
| **Core Quartz** | 트레이딩 (매수/매도/주문정리/보고) + 백테스트 | Spring Quartz → PostgreSQL |

### 전체 스케줄 타임라인 (KST)

```
── Cloud Scheduler (데이터 파이프라인) ──────────────────────

06:05  morning-economic-data     → 경제데이터 수집 (standalone)
       📊 미국장 마감(05:00 KST) 후 최신 경제지표/주가 반영

22~06  news-collection           → 뉴스 수집 (1분 간격, 미국장)
06~22  news-collection-offhours  → 뉴스 수집 (5분 간격, 비미장)

23:40  evening-pipeline          → 이브닝 파이프라인 (pipeline, 자동 체이닝)
       ├─ [1단계] 경제 데이터 수집
       │   - FRED 경제 지표 (CPI, NFP, ISM PMI 등)
       │   - Yahoo Finance 시장 데이터 + 종목 35개
       │   - MongoDB daily_stock_data 업데이트
       │
       ├─ [2단계] 기술적 분석 + 감정 분석 (병렬, 자동 트리거)
       │   - SMA/RSI/MACD 기술적 지표
       │   - 뉴스 감정 분석
       │
       └─ [3단계] Vertex AI 예측 (기술적 분석 완료 시 자동 트리거)
           - 🤖 Transformer 모델 Fine-tuning/Full Training
           - GPU: NVIDIA Tesla T4 (us-central1)
           - 예측 결과 MongoDB 저장

00:20  stock-recommendation      → 종목 추천 (standalone)
       📊 Composite Score 기반 (AI + Technical + Sentiment)
       └─ 이브닝 파이프라인 완료 후 ~40분 여유

── Core Quartz (트레이딩) ──────────────────────────────────

00:30  AutoBuyJobAdapter         → 자동 매수
       💰 미국 장 개장 1시간 후 (변동성 안정화)
       - 미국 정규장 개장: 23:30 (09:30 ET)
       - 초기 변동성 회피 → 트렌드 확정 후 진입

매 1분  AutoSellJobAdapter       → 자동 매도 체크
       🔄 손절/익절 조건 확인 (미국 시장 시간만)

06:30  CleanupOrdersJobAdapter   → 미체결 주문 정리
       🧹 장 마감 후 미체결/실패 주문 처리

07:00  PortfolioProfitReportJob  → 포트폴리오 수익률 보고
       📊 일일 실적 리포트 + Slack 알림

── Core Quartz (백테스트) ──────────────────────────────────

일 02:00  CanonicalBacktestJob   → PUBLISHED 전략 대표 백테스트
매일 03:00  BacktestCleanupJob   → RUNNING 타임아웃, 초과 아카이브 정리
```

### source 구분 (cascade 제어)

| source | 발생 상황 | cascade 동작 |
|--------|----------|-------------|
| `"pipeline"` | Cloud Scheduler evening-pipeline | 경제데이터 → 분석 → Vertex AI 자동 체이닝 |
| `"standalone"` | Admin API, Cloud Scheduler 단독, Quartz 등 | 요청한 작업만 실행, 후속 트리거 없음 |

## Cloud Scheduler 관리

### Job 목록 조회

```bash
gcloud scheduler jobs list --location=asia-northeast3
```

### Job 상태 확인

```bash
gcloud scheduler jobs describe evening-pipeline --location=asia-northeast3
gcloud scheduler jobs describe stock-recommendation --location=asia-northeast3
gcloud scheduler jobs describe morning-economic-data --location=asia-northeast3
```

### Job 수동 실행

```bash
# 이브닝 파이프라인 수동 실행 (cascade 포함)
gcloud scheduler jobs run evening-pipeline --location=asia-northeast3

# 경제데이터 수집만 (standalone)
gcloud scheduler jobs run morning-economic-data --location=asia-northeast3

# 종목 추천만 (standalone)
gcloud scheduler jobs run stock-recommendation --location=asia-northeast3
```

### Job 일시 중지/재개

```bash
# 일시 중지
gcloud scheduler jobs pause evening-pipeline --location=asia-northeast3

# 재개
gcloud scheduler jobs resume evening-pipeline --location=asia-northeast3
```

### Terraform 관리

Cloud Scheduler Job은 `terraform/scheduler.tf`에서 Infrastructure as Code로 관리됩니다.

- **데이터 파이프라인**: `evening-pipeline`, `morning-economic-data`, `stock-recommendation`, 뉴스 수집 등 (현재 활성)
- **Core API용 (전환 시)**: `core-auto-buy`, `core-auto-sell`, `core-cleanup-orders`, `core-portfolio-report`, `core-canonical-backtest`, `core-backtest-cleanup` — 6개 잡이 동일 파일에 주석으로 추가됨. Core API를 Cloud Run으로 전환할 때 주석 해제 후 `terraform apply`로 활성화.

```bash
cd terraform
terraform plan   # 변경사항 확인
terraform apply  # 적용
```

## Core Quartz 관리

### REST API를 통한 제어

#### 스케줄러 시작/중지/상태

```bash
# 상태 조회
curl -X GET http://localhost:10010/api/scheduler/status

# 시작
curl -X POST http://localhost:10010/api/scheduler/start

# 중지
curl -X POST http://localhost:10010/api/scheduler/stop
```

#### 등록된 스케줄 조회

```bash
curl -X GET http://localhost:10010/api/scheduler/schedules
```

#### 스케줄 일시 중지/재개

```bash
# 일시 중지
curl -X POST http://localhost:10010/api/scheduler/schedules/{triggerName}/pause

# 재개
curl -X POST http://localhost:10010/api/scheduler/schedules/{triggerName}/resume
```

### Job 목록 (Core Quartz)

| # | Job 이름 | 실행 시간 | Cron 표현식 | 역할 |
|---|----------|----------|-------------|------|
| 1 | autoBuyJob | 00:30 (매일) | `0 30 0 * * ?` | 자동 매수 |
| 2 | cleanupOrdersJob | 06:30 (매일) | `0 30 6 * * ?` | 미체결 주문 정리 |
| 3 | portfolioProfitReportJob | 07:00 (매일) | `0 0 7 * * ?` | 포트폴리오 수익률 보고 |
| 4 | autoSellJob | **매 1분** | SimpleSchedule | 자동 매도 체크 |
| 5 | canonicalBacktestJob | 일 02:00 | `0 0 2 ? * SUN` | 대표 백테스트 |
| 6 | backtestCleanupJob | 매일 03:00 | `0 0 3 * * ?` | 백테스트 데이터 정리 |
| 7 | kisAccountTrashCleanup | 매일 03:30 | `30 3 * * *` | KIS 계좌 휴지통 정리 — A+ 모델 (deleted_at + 7일 경과 row hard delete). 엔드포인트: `POST /api/internal/scheduler/kis-account-trash-cleanup`. Terraform: `core_kis_account_trash_cleanup`. |

### Docker를 통한 제어

```bash
# Core 컨테이너 재시작
docker-compose restart quantiq-core

# 로그 확인
docker-compose logs -f quantiq-core | grep -i "scheduler"
```

### application.yml 설정

```yaml
spring:
  quartz:
    auto-startup: true
    startup-delay: 10
    overwrite-existing-jobs: false
    job-store-type: jdbc
    jdbc:
      initialize-schema: never
    properties:
      org.quartz.scheduler.instanceName: QuantIQScheduler
      org.quartz.scheduler.instanceId: AUTO
      org.quartz.jobStore.isClustered: true
      org.quartz.threadPool.threadCount: 10
```

## 모니터링

### Cloud Scheduler 모니터링

```bash
# 최근 실행 이력 (GCP Console 또는 gcloud)
gcloud scheduler jobs describe evening-pipeline --location=asia-northeast3 \
  --format="table(name, state, lastAttemptTime, scheduleTime)"
```

### Quartz 다음 실행 시간 확인

```bash
docker-compose exec postgresql psql -U quantiq_user -d quantiq << 'EOF'
SELECT
    trigger_name,
    to_timestamp(next_fire_time / 1000) AT TIME ZONE 'Asia/Seoul' as next_run_kst,
    to_timestamp(prev_fire_time / 1000) AT TIME ZONE 'Asia/Seoul' as prev_run_kst,
    trigger_state
FROM quartz_triggers
ORDER BY next_fire_time;
EOF
```

### 실행 중인 Job 확인

```bash
docker-compose exec postgresql psql -U quantiq_user -d quantiq << 'EOF'
SELECT
    trigger_name, job_name,
    to_timestamp(fired_time / 1000) AT TIME ZONE 'Asia/Seoul' as fired_time_kst,
    state, instance_name
FROM quartz_fired_triggers
WHERE state = 'EXECUTING';
EOF
```

### 실행 이력 (로그 기반)

```bash
# Data Engine 파이프라인 로그
docker-compose logs data-engine --since 24h | grep -E "(EconomicData|Technical|Sentiment|Vertex|Recommendation)"

# Core 트레이딩 로그
docker-compose logs quantiq-core --since 24h | grep -E "(자동 매수|자동 매도|주문 정리|수익 보고)"

# 에러만
docker-compose logs --since 24h | grep -i "error\|❌\|실패"
```

### Trigger 상태 설명

| 상태 | 설명 |
|------|------|
| `WAITING` | 다음 실행을 기다리는 정상 상태 |
| `PAUSED` | 일시 중지된 상태 |
| `ACQUIRED` | 실행을 위해 획득된 상태 |
| `EXECUTING` | 현재 실행 중 |
| `COMPLETE` | 실행 완료 (재실행 없음) |
| `BLOCKED` | 이전 실행이 완료되지 않아 대기 중 |
| `ERROR` | 오류 상태 |

## 데이터베이스 직접 관리

### PostgreSQL 접속

```bash
docker-compose exec postgresql psql -U quantiq_user -d quantiq
```

### 유용한 쿼리

#### 모든 Job 목록 조회

```sql
SELECT job_name, job_group, job_class_name, is_durable
FROM quartz_job_details;
```

#### 스케줄 상세 정보

```sql
SELECT
    t.trigger_name, t.job_name, t.trigger_state,
    ct.cron_expression, ct.time_zone_id,
    to_timestamp(t.next_fire_time / 1000) AT TIME ZONE 'Asia/Seoul' as next_run,
    to_timestamp(t.prev_fire_time / 1000) AT TIME ZONE 'Asia/Seoul' as prev_run
FROM quartz_triggers t
LEFT JOIN quartz_cron_triggers ct ON t.trigger_name = ct.trigger_name
ORDER BY t.next_fire_time;
```

#### 일시 중지된 스케줄 확인

```sql
SELECT trigger_name, job_name, trigger_state
FROM quartz_triggers WHERE trigger_state = 'PAUSED';
```

#### 스케줄러 클러스터 상태

```sql
SELECT instance_name,
    to_timestamp(last_checkin_time / 1000) AT TIME ZONE 'Asia/Seoul' as last_checkin,
    checkin_interval
FROM quartz_scheduler_state;
```

### 수동 스케줄 조작 (주의)

```sql
-- ⚠️ REST API 사용 권장, 직접 DB 조작은 비상시에만
UPDATE quartz_triggers SET trigger_state = 'PAUSED' WHERE trigger_name = 'autoBuyTrigger';
UPDATE quartz_triggers SET trigger_state = 'WAITING' WHERE trigger_name = 'autoBuyTrigger';
```

## 트러블슈팅

### 문제 1: Cloud Scheduler Job이 실행되지 않음

```bash
# Job 상태 확인
gcloud scheduler jobs describe evening-pipeline --location=asia-northeast3

# 수동 실행으로 테스트
gcloud scheduler jobs run evening-pipeline --location=asia-northeast3

# Pub/Sub 구독 확인
gcloud pubsub subscriptions list --filter="topic:economic-data-update-request"

# Data Engine 로그 확인
docker-compose logs data-engine --since 1h | grep "economic"
```

### 문제 2: 파이프라인 체이닝이 동작하지 않음

source가 `"pipeline"`인지 확인:

```bash
# Data Engine 로그에서 source 확인
docker-compose logs data-engine | grep "source"

# Pub/Sub 메시지 내용 확인 (에뮬레이터)
curl http://localhost:8681/v1/projects/quantiq-local/subscriptions
```

### 문제 3: Quartz Job이 실행되지 않음

```bash
# 스케줄러 상태 확인
curl http://localhost:10010/api/scheduler/status

# Trigger 상태 확인
docker-compose exec postgresql psql -U quantiq_user -d quantiq \
  -c "SELECT trigger_name, trigger_state FROM quartz_triggers;"

# PAUSED 상태면 재개
curl -X POST http://localhost:10010/api/scheduler/schedules/{triggerName}/resume
```

### 문제 4: Quartz 스케줄러가 시작되지 않음

```bash
# PostgreSQL 연결 확인
docker-compose logs quantiq-core | grep -i "connection.*failed"

# Flyway 마이그레이션 확인
docker-compose logs quantiq-core | grep -i "flyway"

# Quartz 테이블 존재 확인
docker-compose exec postgresql psql -U quantiq_user -d quantiq -c "\dt quartz_*"
```

### 문제 5: Job이 중복 실행됨

```sql
-- 락 상태 확인
SELECT * FROM quartz_locks;

-- 클러스터링 설정 확인
-- application.yml: org.quartz.jobStore.isClustered: true
```

## 성능 튜닝

### Quartz 쓰레드 풀 조정

```yaml
spring:
  quartz:
    properties:
      org.quartz.threadPool.threadCount: 10
      org.quartz.threadPool.threadPriority: 5
```

### 데이터베이스 커넥션 풀

```yaml
spring:
  datasource:
    hikari:
      maximum-pool-size: 20
      minimum-idle: 5
      connection-timeout: 30000
```

### 오래된 실행 이력 삭제

```sql
DELETE FROM quartz_fired_triggers
WHERE state IN ('COMPLETE', 'ERROR')
  AND fired_time < EXTRACT(EPOCH FROM NOW() - INTERVAL '30 days') * 1000;
```
