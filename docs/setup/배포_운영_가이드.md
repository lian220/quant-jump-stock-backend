## 로컬 배포

전체 시스템은 **Docker Compose**를 통해 관리됩니다.

### 시스템 구성

```
quantiq/
├── quantiq-core/           # Spring Boot (Kotlin)
├── quantiq-data-engine/    # FastAPI (Python)
├── docker-compose.yml      # 서비스 오케스트레이션
└── .env                    # 환경 변수 설정
```

### 배포 순서

1. **환경 변수 설정**
```bash
# .env 파일 생성 (.env.sample 참고)
cp .env.sample .env

# 필수 환경 변수 설정
vim .env
```

2. **Docker Compose로 시작**
```bash
# 모든 서비스 시작
docker-compose up -d

# 로그 확인
docker-compose logs -f
```

3. **헬스 체크**
```bash
# Spring Boot 헬스 체크
curl http://localhost:10010/actuator/health

# Python Engine 헬스 체크
curl http://localhost:10020/health
```

## 포트 매핑

| 서비스 | 내부 포트 | 호스트 포트 | 용도 |
|--------|---------|------------|------|
| **Spring Core** | 8080 | **10010** | REST API, 스케줄러 |
| **Python Engine** | 8000 | **10020** | 데이터 수집, 분석 엔진 |
| **MongoDB** | 27017 | 27017 | NoSQL 데이터베이스 |
| **PostgreSQL** | 5432 | 5432 | RDB 데이터베이스 |
| **Pub/Sub Emulator** | 8681 | 8681 | 메시지 브로커 (GCP Pub/Sub 에뮬레이터) |
| **Pub/Sub Emulator UI** | 8680 | 8680 | Pub/Sub 에뮬레이터 웹 UI |

### 포트 충돌 해결

```bash
# 포트 사용 중인 프로세스 확인
lsof -i :10010
lsof -i :10020

# 프로세스 종료
kill -9 <PID>

# 또는 docker-compose.yml에서 포트 변경
```

## 환경 설정

### 필수 환경 변수

`.env` 파일에 다음 변수들을 설정해야 합니다:

```bash
# ===== API Keys =====
FRED_API_KEY=your_fred_api_key_here
KIS_APP_KEY=your_kis_app_key_here
KIS_APP_SECRET=your_kis_app_secret_here
SLACK_BOT_TOKEN=xoxb-your-slack-bot-token
SLACK_CHANNEL_ID=C1234567890

# ===== Database =====
MONGODB_URI=mongodb://mongodb:27017/quantiq
POSTGRES_HOST=postgresql
POSTGRES_PORT=5432
POSTGRES_DB=quantiq
POSTGRES_USER=quantiq_user
POSTGRES_PASSWORD=quantiq_password

# ===== Pub/Sub =====
PUBSUB_EMULATOR_HOST=localhost:8681
PUBSUB_PROJECT_ID=quantiq-local

# ===== Application =====
SPRING_PROFILES_ACTIVE=local
LOG_LEVEL=INFO
```

### 환경별 설정

#### 로컬 개발 환경
```yaml
# application-local.yml
spring:
  profiles: local
  datasource:
    url: jdbc:postgresql://localhost:5432/quantiq
logging:
  level:
    com.quantiq: DEBUG
```

#### 프로덕션 환경
```yaml
# application-prod.yml
spring:
  profiles: prod
  datasource:
    url: jdbc:postgresql://db.production.com:5432/quantiq
    hikari:
      maximum-pool-size: 20
logging:
  level:
    com.quantiq: INFO
```

## 기본 명령어

### 시작 및 중지

```bash
# 모든 서비스 시작
docker-compose up -d

# 특정 서비스만 시작
docker-compose up -d quantiq-core
docker-compose up -d quantiq-data-engine

# 모든 서비스 정지
docker-compose stop

# 모든 서비스 제거 (컨테이너 삭제)
docker-compose down

# 볼륨 포함 완전 제거 (데이터 삭제 주의!)
docker-compose down -v
```

### 빌드 및 재시작

```bash
# 이미지 재빌드 후 시작
docker-compose up --build -d

# 특정 서비스만 재빌드
docker-compose build quantiq-core
docker-compose up -d quantiq-core

# 서비스 재시작 (이미지 재빌드 없이)
docker-compose restart
```

### 로그 확인

```bash
# 전체 로그 확인 (실시간)
docker-compose logs -f

# 특정 서비스 로그만 확인
docker-compose logs -f quantiq-core
docker-compose logs -f quantiq-data-engine

# 최근 100줄만 보기
docker-compose logs --tail=100 quantiq-core

# 특정 시간 이후 로그
docker-compose logs --since 2026-01-31T09:00:00 quantiq-core
```

### 컨테이너 관리

```bash
# 실행 중인 컨테이너 확인
docker-compose ps

# 특정 컨테이너 접속
docker-compose exec quantiq-core bash
docker-compose exec quantiq-data-engine bash
docker-compose exec postgresql psql -U quantiq_user -d quantiq
docker-compose exec mongodb mongosh quantiq

# 컨테이너 리소스 사용량
docker stats
```

## 프로덕션 배포

### 배포 전 체크리스트

- [ ] 환경 변수 설정 완료 (.env 파일)
- [ ] API 키 발급 및 검증 (FRED, KIS, Slack)
- [ ] 데이터베이스 백업
- [ ] 디스크 공간 확인 (최소 10GB 권장)
- [ ] 방화벽 설정 (필요한 포트 오픈)
- [ ] SSL 인증서 설정 (HTTPS)
- [ ] 모니터링 도구 설정 (Grafana, Prometheus)

### 배포 단계

#### 1. 코드 배포

```bash
# Git에서 최신 코드 받기
git pull origin main

# JVM 빌드 (로컬 테스트용)
cd quantiq-core
./gradlew clean build -x test

# Native Image 빌드 (프로덕션용, CI에서 자동 실행)
# ./gradlew nativeCompile -x test  # ~12분 소요

cd ../quantiq-data-engine
pytest
```

#### 2. 데이터베이스 백업

```bash
# PostgreSQL 백업
docker-compose exec postgresql pg_dump -U quantiq_user quantiq > backup-$(date +%Y%m%d).sql

# MongoDB 백업
docker-compose exec mongodb mongodump --db quantiq --out /backup
```

#### 3. 서비스 중지 및 업데이트

```bash
# 프로덕션: GitHub Actions가 자동 배포 (main push 시)
# - GraalVM Native Image 빌드 → Docker Build → Push to AR → VM 배포
# - 다운타임 ~5초 (Native Image 시작 ~2초)

# 수동 배포 (VM에서):
cd /opt/quant-jump-stock
docker compose -f docker-compose.prod.yml pull core
docker compose -f docker-compose.prod.yml up -d --no-deps core
```

> **Core API Cloud Run 전환 예정**: Terraform에 Core Run 서비스·SA·Push 구독·Cloud Scheduler 6개 잡이 반영되어 있음. 전환 시 `deploy-core.yml`에서 Cloud Run 배포 잡 주석 해제 후 트래픽 전환. 상세: [클라우드런 전환 Phase1](../architecture/클라우드런_전환_Phase1.md).

#### 4. 헬스 체크

```bash
# 애플리케이션 헬스 체크
curl http://localhost:10010/actuator/health
curl http://localhost:10020/health

# 데이터베이스 연결 확인
docker-compose exec postgresql psql -U quantiq_user -d quantiq -c "SELECT 1"
docker-compose exec mongodb mongosh --eval "db.adminCommand('ping')"
```

#### 5. 모니터링

```bash
# 로그 모니터링
docker compose -f docker-compose.prod.yml logs -f --tail=100

# 리소스 사용량 모니터링 (Native Image: RSS ~170MB / 384M 제한)
docker stats

# VM 메모리 확인
free -h
```

### 롤백 절차

```bash
# 1. 이전 버전 이미지로 롤백
docker-compose down
docker tag quantiq-core:latest quantiq-core:backup
docker tag quantiq-core:previous quantiq-core:latest
docker-compose up -d

# 2. 데이터베이스 롤백 (백업 복원)
docker-compose exec postgresql psql -U quantiq_user -d quantiq < backup-20260131.sql
```

## 운영 모니터링

### 주요 메트릭

| 메트릭 | 임계값 | 조치 |
|--------|--------|------|
| CPU 사용률 | > 80% | 스케일 아웃 고려 |
| 메모리 사용률 | > 85% | 메모리 증설 |
| 디스크 사용률 | > 90% | 로그 정리, 디스크 증설 |
| API 응답 시간 | > 1초 | 쿼리 최적화 |
| Pub/Sub 미확인 메시지 | > 1000 | Pull 구독 처리량 확인 |

### 알림 설정

```bash
# Slack 알림 테스트
curl -X POST http://localhost:10010/api/notifications/test

# 주요 알림 종류
# - 서비스 다운
# - API 에러율 > 5%
# - 데이터베이스 연결 실패
# - 디스크 공간 부족
```

## 트러블슈팅

### 서비스가 시작되지 않음

```bash
# 1. 로그 확인
docker-compose logs quantiq-core

# 2. 환경 변수 확인
docker-compose config

# 3. 포트 충돌 확인
lsof -i :10010
```

### 데이터베이스 연결 실패

```bash
# PostgreSQL 상태 확인
docker-compose exec postgresql pg_isready

# MongoDB 상태 확인
docker-compose exec mongodb mongosh --eval "db.serverStatus()"

# 네트워크 확인
docker-compose exec quantiq-core ping postgresql
```

### Pub/Sub 메시지 문제

```bash
# 로컬 (에뮬레이터): Pub/Sub Emulator UI에서 확인
# http://localhost:8680

# 프로덕션 (GCP): gcloud CLI로 확인
gcloud pubsub subscriptions pull <subscription-name> --auto-ack --limit=10

# 미확인 메시지 수 확인
gcloud pubsub subscriptions describe <subscription-name> \
  --format="value(numUndeliveredMessages)"
```
