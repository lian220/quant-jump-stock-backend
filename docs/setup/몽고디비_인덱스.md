## daily_stock_data 컬렉션 인덱스

백테스트 성능 최적화를 위한 필수 인덱스.

**성능 개선 효과:**
- MongoDB 쿼리 속도: 20-30초 → 3-5초 (약 85% 개선)
- 백테스트 전체 시간: 56초 → 42초 (약 25% 개선)

### 자동 생성 스크립트 (권장)

```bash

python scripts/create_mongo_indexes.py "mongodb+srv://user:password@cluster.mongodb.net/stock_trading"
```

## sentiment_analysis/stock_predictions 성능 핫픽스

2026-02 기준 로컬/운영 공통 성능 이슈 대응:

- `sentiment_analysis`에 `date` 인덱스 부재 -> `COLLSCAN` 발생
- `stock_predictions.date` 타입 혼재(`date` + `string`) -> 조회/업서트 충돌 가능

### 수동 적용 절차 (로컬/운영 공통)

1. `sentiment_analysis` 인덱스 보장

```javascript
db.sentiment_analysis.createIndex({ date: 1, ticker: 1 }, { name: "date_ticker_idx" })
```

2. `stock_predictions.date` 타입 정규화 (문자열 -> Date)

```javascript
db.stock_predictions.updateMany(
  { date: { $type: "string" } },
  [
    {
      $set: {
        date: {
          $convert: {
            input: "$date",
            to: "date",
            onError: "$date",
            onNull: "$date"
          }
        }
      }
    }
  ]
)
```

3. 유니크 충돌 레거시 정리

- `(ticker, date)` 유니크 인덱스 충돌이 나는 경우,
- 동일 `(ticker, parsed_date)`가 이미 Date 문서로 있는 문자열 date 레거시 문서를 삭제합니다.

```javascript
// 충돌 후보 확인 예시
db.stock_predictions.aggregate([
  { $match: { date: { $type: "string" } } },
  { $project: { ticker: 1, raw_date: "$date" } },
  { $limit: 20 }
])
```

### 확인 명령어

```javascript
// 인덱스 확인
db.sentiment_analysis.getIndexes()

// date 타입 분포 확인
db.stock_predictions.aggregate([
  { $project: { t: { $type: "$date" } } },
  { $group: { _id: "$t", n: { $sum: 1 } } }
])

// sentiment_analysis 인덱스 사용 확인
db.sentiment_analysis.find(
  { date: "2026-02-17" },
  { _id: 0, ticker: 1, average_sentiment_score: 1 }
).explain("executionStats")
```

## news_sentiment 컬렉션 인덱스

뉴스 감정 분석 데이터 조회 성능을 위한 인덱스 설정.

### 필수 인덱스

```javascript
// MongoDB Shell 접속
mongosh "mongodb://quantiq_user:quantiq_password@localhost:27017/stock_trading?authSource=admin"

// 1. 종목 + 날짜별 조회 (추천 시스템용)
db.news_sentiment.createIndex(
  { ticker: 1, date: -1 },
  { name: "ticker_date_idx" }
)

// 2. 종목 + 발행시간 (최신 뉴스 우선)
db.news_sentiment.createIndex(
  { ticker: 1, published_at: -1 },
  { name: "ticker_published_idx" }
)

// 3. URL 중복 방지 (unique)
db.news_sentiment.createIndex(
  { ticker: 1, url: 1 },
  { name: "ticker_url_unique_idx", unique: true }
)

// 4. TTL 인덱스 (90일 후 자동 삭제)
db.news_sentiment.createIndex(
  { created_at: 1 },
  { expireAfterSeconds: 7776000, name: "ttl_90days_idx" }  // 90일 = 7776000초
)

// 5. 감정 점수 + 관련도 (고품질 뉴스 필터)
db.news_sentiment.createIndex(
  { ticker: 1, "sentiment.score": -1, "sentiment.relevance_score": -1 },
  { name: "ticker_quality_idx" }
)
```

### 인덱스 확인

```javascript
// 생성된 인덱스 목록 확인
db.news_sentiment.getIndexes()

// 인덱스 사용 통계
db.news_sentiment.aggregate([
  { $indexStats: {} }
])
```

### 인덱스 삭제 (필요시)

```javascript
// 특정 인덱스 삭제
db.news_sentiment.dropIndex("ticker_date_idx")

// 모든 인덱스 삭제 (_id 제외)
db.news_sentiment.dropIndexes()
```

```bash
db.news_sentiment.createIndex({ ticker: 1, published_at: -1 }, { name: "ticker_published_idx" })
```

## 예상 데이터 규모

- **종목 수**: 35개
- **일 평균 뉴스**: 10건/종목
- **보관 기간**: 90일
- **총 문서 수**: 35 × 10 × 90 = 31,500건
- **예상 용량**: 약 30-50MB (압축 후)

## TTL 정책

- **90일 자동 삭제**: `created_at` 기준으로 90일 지난 문서 자동 삭제
- **디스크 공간 절약**: 오래된 뉴스는 자동 정리
- **추천 근거 보존**: 최근 3개월 뉴스만 보관 (충분)

## 주의사항

1. **unique 인덱스**: ticker + url 조합으로 중복 방지
2. **TTL 작동**: MongoDB가 백그라운드로 60초마다 체크
3. **인덱스 크기**: 인덱스도 메모리 사용, 필요한 것만 생성
4. **복합 인덱스 순서**: 쿼리 패턴에 맞게 필드 순서 중요
