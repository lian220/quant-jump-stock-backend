## 1. 개요

3 축 가중 합산:
- **AI** (weight 0.3, max 10): Vertex AI 가 예측한 상승 확률 (`stock_analysis_results.predictions.rise_probability`)
- **Technical** (weight 0.4, max 3.5): 골든크로스 + RSI + MACD 매수 신호
- **Sentiment** (weight 0.3, max 10): 뉴스 감정 점수 (`sentiment_analysis.average_sentiment_score`)

```
composite_score = 0.3·ai + 0.4·tech + 0.3·sentiment
composite_max = 0.3·10 + 0.4·3.5 + 0.3·10 = 7.4
```

---

## 2. 각 축의 산식

### 2.1 AI Score (0~10)

raw `rise_probability` (% 단위 또는 0~1 normalized) → :

```
normalized = clip(0.5 + rise_pct / (2 × cap_threshold_pct), 0, 1)
                                       ↑ cap = 20% (spec)

if normalized < 0.5:
    ai_score = 0
else:
    ai_score = (normalized − 0.5) × 2 × ai_max     # ai_max = 10
```

| raw rise % | normalized | ai_score |
|-----------|-----------|----------|
| -20% | 0.0 | 0 |
| -10% | 0.25 | 0 |
|  0%  | 0.5  | 0 |
| +10% | 0.75 | 5.0 |
| +20% | 1.0  | 10.0 (cap) |
| +30% | 1.0  | 10.0 (cap) |

### 2.2 Technical Score (0~3.5)

3개 신호 가중 합산:
- `golden_cross == True`: **1.5**
- `rsi < 70`: **1.0**
- `macd_buy_signal == True`: **1.0**

**최대 3.5** (셋 다 만족 시)

### 2.3 Sentiment Score (0~10)

raw `average_sentiment_score` ∈ [-1, +1]:
- `score ≤ 0`: 0
- `score > 0`: `raw × sent_max` (sent_max = 10)

예: raw 0.5 → sentiment_score = 5.0

---

## 3. Composite Score (0~7.4)

`scoring_spec.yaml` load 시 invariant 검증:
- `axes.weight` 합 = 1.0 ± 0.001
- `composite_max = Σ(weight × max)` 일치
- grade thresholds monotonic decreasing
- `negative_policy ∈ {zero, veto}` (PR 3b)

### Confidence (달성도)
```
confidence = composite / composite_max
```
0.0 ~ 1.0 범위. Slack "달성도 N%" 표시.

---

## 4. Grade (S/A/B/C/D)

composite_score 임계:

| Grade | composite ≥ | 의미 |
|-------|------------|------|
| **S** | 6.0 | 매우 강한 매수 |
| **A** | 4.5 | 강한 매수 |
| **B** | 3.0 | 보통 매수 |
| **C** | 1.5 | 약한 매수 |
| **D** | 0.0 | 신호 없음 |

PG `prediction_results.composite_grade` 컬럼에 저장.

---

## 5. Recommendation Label (STRONG/RECOMMEND/WATCH/NONE)

confidence + tech_signals 조합:

| Label | confidence ≥ | tech_signals ≥ | Slack 표시 |
|-------|--------------|----------------|-----------|
| **STRONG** | 0.65 | 3 | 🟢 강력 추천 |
| **RECOMMEND** | 0.45 | 2 | 🟡 추천 |
| **WATCH** | 0.30 | 1 | 🟠 관심 종목 |
| **NONE** | — | — | ⚪ 추천 없음 |

PR 2 (2026-05-21) 부터 label/emoji 는 `scoring_spec.yaml.recommendation_labels` SSoT lazy 로드.

## 6. Negative AI Veto (PR 3b, 2026-05-22)

**spec.axes.ai.negative_policy = "veto"** 조건 하에 발동.

| 조건 | 결과 |
|------|------|
| raw rise_pct < 0 (또는 normalized < 0.5) | `composite_score = 0`, `grade = "D"`, `recommendation_label = "NONE"`, `veto_reasons = ("ai_negative",)` |

**의도**:
- "AI 하락 예측 + 시스템 강력 추천" 모순 출력 방지 (2026-05-20 사용자 의문 사건 대응)
- Taleb asymmetric risk: 가시적 신뢰 손상 회피 우선

**Rollback** (yaml flip):
```yaml
axes:
  ai:
    negative_policy: zero   # was: veto
```
`scoring_spec.yaml` 만 수정 + push → CI 자동 재배포 (~10분). V70 PG 컬럼은 그대로 NULL 로 회복.

## 7. 추천 필터

`scoring_spec.yaml.recommendation_filter`:
- `min_composite_score: 2.0` (PR 3d 에서 3.0 상향 검토)
- `max_recommendations: 5` (Slack 메시지 상위 N개)

`buy_criteria.filter_candidates` → composite_score 내림차순 정렬 후 상위 N 선정.

## 8. 데이터 소스 비대칭 (PR 2 가시화)

| 호출 경로 | 데이터 fallback | 영향 |
|-----------|----------------|------|
| `sync_service` → PG `prediction_results` | **없음** (ADR 0001, 정확한 날짜만) | 일관성 우선 |
| `comprehensive_report` → Slack | **7일 lookback** (data freshness 보장) | `effective_prediction_date` 로 명시 노출 |

PR 2 가 `effective_prediction_date` 를 Slack 헤더에 명시 ("⚠ AI 예측은 X 자료 없어 Y 기준값 사용") 하여 audit 추적 가능.
