### 🔴 HIGH

- [ ] **[Data Engine] Pub/Sub 재시도성 에러 소실** — ⚠️ **유효 (부분 개선)**
  - 파일: `adapter/input/pubsub/push_handler.py:121-147` (Push=**prod 경로**), `subscriber.py:130-132` (Pull=로컬/VM)
  - 개선됨: `NonRetryableError` 클래스 도입(`subscriber.py:20`) + 핸들러가 데이터오류(ValueError/KeyError/TypeError)→`NonRetryableError`, 그 외→generic 재-raise로 구분(`handlers.py:205-233` 등) + Slack 에러 알림
  - **남은 결함**: push_handler의 generic `except Exception`도 `return 200(ACK)`(:147), subscriber는 `message.ack()`(:132) → **재시도성 에러(일시적 DB/네트워크/외부 API 5xx)까지 ACK되어 영구 소실**. 핸들러가 구분한 retryable이 경계에서 다시 뭉개짐. push_handler docstring은 "500→NACK(재시도)"라 적혀 있으나 **실제 500 반환 경로 없음**(문서-코드 불일치)
  - 수정: push_handler가 retryable 예외에 **500 반환**(Pub/Sub 자동 재시도), subscriber는 **nack/예외 rethrow**. NonRetryableError만 ACK

- [ ] **[Data Engine] async 핸들러 타입 불일치** — ✅ **해소 (LOW로 강등 가능)**
  - base `MessageHandler.handle()`는 sync 선언, 일부 핸들러 `async def` override(`handlers.py:251,356,651,898`) → 형식상 타입 불일치는 잔존하나, 두 호출 지점 모두 `asyncio.iscoroutinefunction(handler)`로 올바르게 분기(`subscriber.py:121`, `push_handler.py:113`). **런타임 오류 없음.** 남은 건 타입 순수성(cosmetic) — base를 async 통일 or Protocol 분리 시 깔끔

- [ ] **[Core API] JWT 검증 오류 무시 (인증 우회)** — ✅ **해소 (fail-closed)**
  - 파일: `config/JwtAuthenticationFilter.kt:51-54`
  - 현재: catch에서 `SecurityContextHolder.clearContext()` 호출(:53) → 인증 미설정(anonymous)으로 진행. `validateAccessToken`은 무효 토큰에 null 반환(`JwtService.kt:94`). `SecurityConfig`가 `.anyRequest().authenticated()` 보호 → anonymous는 인가계층에서 401/403. **인증 우회 해소.** `filterChain.doFilter` 호출은 JWT 필터 정상 패턴
  - 선택적 하드닝(취약점 아님): 만료(401) vs 변조(401+보안로그) 구분, 서명 실패 보안 이벤트 로깅
