# 시크릿 회전 절차 (DB / API 키)

prod 환경의 비밀번호·API 키 회전 시 표준 절차. **모든 운영자가 같은 단계를 거치도록** 표준화.

> **본 문서가 다루는 시크릿**: `qjs-env-db-prod` (Supabase Postgres + MongoDB Atlas), `qjs-env-prod` (애플리케이션 시크릿), `qjs-env-common` (공통 설정).
>
> **Vertex AI Job 의 특수성**: Cloud Run 의 secret 마운트가 자동 latest 라도, **Vertex Job 패키지(GCS)는 stale 됨**. 회전 후 반드시 `POST /api/v1/ml/upload` 재호출 필요. 본 단계 누락 시 어제(2026-05-18) 사고 재현. 자세한 회고는 [잔여작업.md](../../../../docs/잔여작업.md) 의 "Vertex AI 사고 대응" 섹션.

## 1. 사전 준비

### 1.1 다운타임 시간대 결정

| 시간대 (KST) | 비활성 Scheduler | 권장도 |
|---|---|---|
| 04:00 ~ 06:00 | 거의 모든 잡 (auto-buy 끝, 미국 장 외) | ⭐⭐⭐ 최적 |
| 13:00 ~ 17:00 | 미국 장 시작 전, 한국 사용자 적음 | ⭐⭐ 양호 |
| 22:00 ~ 24:00 | 미국 장 진행 중 (`evening-pipeline` 17:00 ET 직후) | ⭐ 위험 |
| 00:30 (KST) 직전 | `core-auto-buy` 잡 hit 위험 | ❌ 회피 |

### 1.2 사전 점검

```bash
# 진행 중인 Vertex Job 확인 (RUNNING/PENDING 있으면 회전 후 죽음)
gcloud ai custom-jobs list --region=us-central1 --project=focal-limiter-486614-u8 \
  --filter='state=JOB_STATE_RUNNING OR state=JOB_STATE_PENDING' \
  --format='table(name,state,createTime)'

# 현재 Cloud Run revision 확인 (회전 후 비교용)
gcloud run services describe qjs-core --region=asia-northeast3 \
  --project=focal-limiter-486614-u8 --format='value(status.traffic)'
gcloud run services describe qjs-data-engine --region=asia-northeast3 \
  --project=focal-limiter-486614-u8 --format='value(status.traffic)'
```

## 2. PostgreSQL (Supabase) 비번 회전

### 2.1 Supabase 콘솔에서 Reset

```
https://supabase.com/dashboard/project/{PROJECT_REF}/settings/database
```

- "Database password" 섹션 → `Reset database password` 클릭
- 새 비번 즉시 표시 → **안전한 곳에 임시 보관** (페이지 떠나면 다시 못 봄)
- ⚠️ Reset 누른 **그 순간부터 옛 비번 무효**. 이후 단계 빠르게 진행 (목표 5분 내)

### 2.2 로컬 `.env.db.prod` 갱신

`backend/.env.db.prod` 파일 열어서 `DB_PASSWORD=...` 만 새 비번으로 교체. 다른 키 손대지 않음.

### 2.3 Secret Manager 새 버전 추가

```bash
gcloud secrets versions add qjs-env-db-prod \
  --data-file=/path/to/backend/.env.db.prod \
  --project=focal-limiter-486614-u8
```

성공 출력 예: `Created version [N] of the secret [qjs-env-db-prod].`

### 2.4 옛 버전 disable

```bash
# 직전 버전 N-1 disable
PREV=$(gcloud secrets versions list qjs-env-db-prod \
  --filter='state=ENABLED' --project=focal-limiter-486614-u8 \
  --format='value(name)' --limit=2 | tail -1)
gcloud secrets versions disable $PREV --secret=qjs-env-db-prod \
  --project=focal-limiter-486614-u8

# 확인 — 최신 1개만 enabled 여야 함
gcloud secrets versions list qjs-env-db-prod \
  --project=focal-limiter-486614-u8 --format='table(name,state)'
```

⚠️ **옛 버전 disable 은 새 버전 add 다음에**. 순서 뒤바뀌면 enabled 버전이 0개가 되어 Cloud Run secret mount 실패.

## 3. Cloud Run 새 비번 반영

`latest` 마운트라도 컨테이너가 부팅 시 한 번만 읽으므로 **새 revision 강제 필요**.

### 3.1 새 revision 트리거

```bash
gcloud run services update qjs-core \
  --region=asia-northeast3 --project=focal-limiter-486614-u8 \
  --update-env-vars=SECRET_ROTATE_TS=$(date +%s)

gcloud run services update qjs-data-engine \
  --region=asia-northeast3 --project=focal-limiter-486614-u8 \
  --update-env-vars=SECRET_ROTATE_TS=$(date +%s)
```

> `SECRET_ROTATE_TS` 는 dummy env. 값이 변해야 새 revision 생성. ts 가 같으면 No-op.

### 3.2 Traffic 100% → 새 revision (자동 미전환 회피)

**현재 deploy.yml 정책상 새 revision 이 0% traffic 으로 생성됨** (회고 항목 #2). 수동 전환 필수:

```bash
for svc in qjs-core qjs-data-engine; do
  NEW=$(gcloud run revisions list --service=$svc \
    --region=asia-northeast3 --project=focal-limiter-486614-u8 \
    --limit=1 --format='value(name)' | head -1)
  gcloud run services update-traffic $svc \
    --region=asia-northeast3 --project=focal-limiter-486614-u8 \
    --to-revisions=$NEW=100
done
```

> qjs-core 가 `latestRevision: True` 로 설정되어 있으면 자동 100% (이 경우 skip).

## 4. Vertex AI 패키지 재업로드 (⚠️ 누락 시 사고 재현)

GCS 의 `predict_optimized-latest.tar.gz` 가 옛 비번을 박은 채 stale 상태가 됨. Vertex Job 트리거 시 즉시 `OSError: DB_PASSWORD ...` 또는 `ValueError: DB...` 로 실패.

```bash
TOKEN=$(gcloud auth print-identity-token \
  --audiences=https://qjs-data-engine-e6ryzgbsna-du.a.run.app)
curl -X POST https://qjs-data-engine-e6ryzgbsna-du.a.run.app/api/v1/ml/upload \
  -H "Authorization: Bearer $TOKEN" \
  -w "\nHTTP %{http_code}\n" -s --max-time 120
```

성공 응답:
```json
{"success":true,"message":"패키지 업로드 완료 (vN + latest)","gcs_uri":"gs://...quantiq-ml-package-vN.tar.gz","version":N,...}
```

## 6. MongoDB Atlas 비번 회전 (선택)

`MONGODB_URI` 안의 비번도 같이 회전하려면:

1. Atlas 콘솔: `Database Access` → 해당 user 의 `Edit` → `Edit Password`
2. `MONGODB_URI` 새 비번 반영하여 로컬 `.env.db.prod` 갱신 → §2.3~2.4 와 동일 단계
3. Cloud Run 둘 다 새 revision 강제 (§3) + 패키지 재업로드 (§4)

PostgreSQL 회전과 같은 secret(`qjs-env-db-prod`)에 들어가므로 단일 절차로 통합 가능.

## 7. 사고 시 Rollback

문제 발생 시 옛 secret 버전 다시 enable (5분 이내 시도):

```bash
# v3 가 직전 enabled 였다고 가정
gcloud secrets versions enable 3 --secret=qjs-env-db-prod \
  --project=focal-limiter-486614-u8

# Cloud Run 둘 다 새 revision 다시 (이전 secret mount 반영)
for svc in qjs-core qjs-data-engine; do
  gcloud run services update $svc \
    --region=asia-northeast3 --project=focal-limiter-486614-u8 \
    --update-env-vars=ROLLBACK_TS=$(date +%s)
done

# Supabase 측은 새 비번으로 이미 reset 됐으니 Supabase Reset 다시 또는
# Atlas/Supabase 콘솔에서 옛 비번 일시 복원 불가 — 새 비번 그대로 두고
# Cloud Run 에 새 비번 redeploy 가 빠를 수 있음
```
